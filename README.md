# **AI 화이트보드 숏폼 자동 생성 파이프라인 MVP 구성안**

**기획 회의용 | 기업 요구사항 기반 기술 구성안**

## **1. 프로젝트 목표**

블로그 URL 또는 원문을 입력하면 AI가 핵심 내용을 분석하고, 장면별 대본과 화이트보드 일러스트를 생성한 뒤, **드로잉 애니메이션·한국어 내레이션·자막이 포함된 30~60초 세로형 MP4 영상 초안을 자동으로 제작**하는 MVP를 구현한다.

기업이 강조한 핵심은 화려한 웹 UI가 아니라 **입력부터 영상 생성까지 사람의 개입을 최소화한 AI 파이프라인의 완성도**다.

### **핵심 구현 원칙**

- **자동화:** 콘텐츠 입력 이후 대본·장면·이미지·음성·자막·영상 생성까지 자동 연결
- **화이트보드 스타일:** 단순 이미지 슬라이드가 아닌, 일러스트가 순차적으로 그려지는 영상 구현
- **설명 적합성:** 장면별 일러스트가 내레이션의 핵심 내용을 시각적으로 표현
- **일관성:** 전체 영상에서 흑백 라인아트 기반의 화이트보드 스타일 유지
- **수정 용이성:** 생성된 대본이나 장면을 최소한의 작업으로 수정·재생성할 수 있도록 구성

## **3. 기술 스택 구성**

| **구분** | **기술** | **선정 이유** |
| --- | --- | --- |

| 블로그 추출 | **Requests + BeautifulSoup / ego lite(ego-browser)** | HTML 분석 또는 실제 브라우저 기반 접근을 통해 블로그 본문 추출 |
| 콘텐츠 분석 | **OpenAI API** | 원문 요약 및 핵심 메시지 추출 |

| 이미지 생성 | **OpenAI Image API** | 화이트보드 스타일 일러스트 자동 생성 |
| 데이터 전달 | **JSON** | 장면별 대본·이미지·음성·재생 시간 관리 |
| TTS | **한국어 TTS 엔진** | 내레이션 생성. 초기에는 검증된 macOS `say` 활용 가능 |
| 드로잉 애니메이션 | **whiteboard-animator** | 정적 이미지를 드로잉 영상으로 변환 |
| 영상 전처리 | **FFmpeg** | 코덱 변환 및 파일 처리 |
| 자막 | **SRT** | 장면별 자막 내용과 표시 시간 관리 |
| 최종 영상 합성 | **Remotion** | 장면 연결, 자막 표시 및 MP4 렌더링 |
| 영상 구성 | **React + TypeScript** | Remotion 영상 템플릿 구현 |
| 실행 환경 | **Python + Node.js** | Python 파이프라인과 Remotion 실행 |

### **블로그 본문 추출 기술 비교**

두 방식 모두 블로그 URL을 입력받아 제목과 본문을 추출할 수 있지만, **웹페이지에 접근하고 콘텐츠를 처리하는 방식에서 차이가 있다.**

| **비교 기준** | **Requests + BeautifulSoup** | **ego lite(ego-browser)** |
| --- | --- | --- |
| **처리 방식** | HTTP 요청으로 HTML을 가져와 분석 | 실제 브라우저를 실행해 페이지 탐색 |
| **JavaScript 동적 콘텐츠** | 별도 처리 필요 | 브라우저에서 실행 가능 |
| **네이버 블로그 iframe** | iframe URL을 별도로 요청 | 브라우저에서 iframe 처리 가능 |
| **지연 로딩 콘텐츠** | 별도 처리 필요 | 스크롤 등을 통한 처리 가능 |
| **실행 속도** | 상대적으로 빠르고 가벼움 | 브라우저 실행으로 추가 비용 발생 |
| **실행 환경** | Python 환경 | ego lite 브라우저 및 실행 환경 필요 |
| **Python 연동** | 직접 연동 가능 | 별도 프로세스 또는 인터페이스 연동 필요 |
| **MVP 적용** | 가능 | 가능 |

**Requests + BeautifulSoup**

- HTML 구조가 명확한 블로그에서 효율적으로 본문 추출 가능
- Python 기반 AI 파이프라인과 직접 연결 가능
- 실행 환경이 비교적 단순하고 가벼움
- JavaScript로 생성되는 콘텐츠는 별도 대응 필요

**ego lite(ego-browser)**

- 실제 브라우저 환경에서 블로그 페이지에 접근
- JavaScript 실행 및 스크롤을 통한 동적 콘텐츠 처리에 유리
- iframe 및 지연 로딩 콘텐츠에 대응 가능
- 별도의 브라우저 실행 환경과 프로세스 연동이 필요

**기술 선정 방향**

기업의 핵심 요구사항은 크롤링 기능 자체가 아니라 **블로그 콘텐츠를 정확하게 추출해 AI 영상 생성 파이프라인으로 전달하는 것**이다.

따라서 두 기술 모두 요구사항을 충족할 수 있으며, 실제 블로그 URL을 대상으로 **본문 추출 정확도·성공률·처리 시간·실행 환경**을 비교해 최종 적용 기술을 결정한다.

## **5. 핵심 데이터 구조: scenes.json**

전체 자동화를 위해 각 장면의 정보를 JSON 형태로 관리한다.

최종적으로 사용할 수 있는 구조의 예시

```json
{
  "title": "미스터리 기차역 이야기",
  "aspect_ratio": "9:16",
  "fps": 30,
  "target_duration": 45,
  "style_prompt": "Black and white whiteboard line art",
  "scenes": [
    {
      "id": 1,
      "narration": "폭설로 고립된 외딴 기차역.",
      "image_prompt": "A remote train station covered in snow",
      "image": "assets/images/scene_01.png",
      "audio": "assets/audio/scene_01.wav",
      "video": "videos/scene_01.mp4",
      "subtitle": "assets/subtitles/scene_01.srt",
      "duration": null
    }
  ]
}
```

실제 구현에서는 다음과 같이 처리한다.

1. OpenAI API가 장면별 대본과 이미지 프롬프트 생성
2. 이미지 생성 API가 장면별 PNG 파일 저장
3. TTS 엔진이 음성 파일 생성
4. Python이 실제 음성 길이를 측정하고 `duration` 기록
5. `whiteboard-animator`가 장면별 영상 생성
6. Remotion이 JSON 데이터를 기반으로 장면을 자동 배치

**장면 수를 코드에 고정하지 않고 JSON 데이터에 따라 자동 변경하는 것이 핵심**

## **6. 기업이 강조한 품질 검증 방안**

이번 프로젝트는 단순히 영상이 생성되는 것뿐 아니라 결과물의 활용 가능성도 확인해야 함

따라서 다음 항목을 검증하도록 설계한다.

| **검증 항목** | **검증 방법** |
| --- | --- |
| 자동화 성공 여부 | URL 입력부터 MP4 출력까지 수동 개입 없이 실행 |
| 대본 품질 | 원문의 핵심 정보 누락·왜곡 여부 확인 |
| 장면 적합성 | 내레이션과 이미지의 의미적 연결 확인 |
| 화풍 일관성 | 장면 간 선 굵기·색상·구도 비교 |
| 드로잉 품질 | 그림이 자연스럽게 나타나는지 확인 |
| 음성·자막 동기화 | 실제 발화와 자막 표시 시간 비교 |
| 영상 길이 | 최종 영상이 30~60초 범위인지 확인 |
| 생성 시간 | 입력부터 최종 MP4까지 소요 시간 측정 |
| 생성 비용 | 콘텐츠 1건당 API 사용 비용 계산 |
| 수정 용이성 | 대본 또는 이미지 수정 후 재렌더 가능 여부 확인 |

### **특히 중요한 검증 항목**

**장면 적합성과 드로잉 품질은 별도로 평가해야 함**

예를 들어 AI가 대본에 적합한 그림을 생성하더라도, `whiteboard-animator`가 그림을 무작위 순서로 그리면 설명 흐름이 자연스럽지 않을 수 있음

따라서 두 가지를 구분해서 확인해야 함

- **AI 이미지 품질:** 대본을 정확하게 시각화했는가?
- **드로잉 품질:** 그림이 자연스럽고 이해하기 쉬운 순서로 등장하는가?

이 부분은 기업이 강조한 ‘설명 과정을 직관적으로 표현’한다는 목표와 직접 연결됨

## **7. MVP 개발 우선순위**

| **P0** | AI 이미지 생성 API 연동 | 장면별 화이트보드 이미지 자동 생성 |
| **P0** | TTS·드로잉 자동화 | 이미지 + 음성 → 장면별 영상 |
| **P0** | Remotion 동적 렌더링 | 장면 수·길이 자동 반영 |
| **P0** | 전체 파이프라인 통합 | 입력 한 번으로 MP4 생성 |
| **P1** | 화풍 일관성 개선 | 이미지 스타일 안정화 |
| **P1** | 대본·장면 수정 | JSON 수정 및 부분 재생성 |
| **P1** | 3개 이상 주제 테스트 | 재현성 검증 |
| **P1** | 처리 시간·비용 측정 | 자동화 효과 검증 |

| **P2** | 추가 애니메이션 | Anime.js 등 활용 |

여기서 **P0가 완료되면 기업이 기대하는 핵심 MVP를 시연할 수 있음**

P1은 영상의 품질과 실무 활용 가능성을 높이는 작업이고, P2는 추가 기능에 해당함

# **9. 최종 제안 구성**

### **프로젝트명**

**AI 기반 화이트보드 숏폼 자동 생성 파이프라인**

### **프로젝트 목적**

블로그 콘텐츠를 AI로 분석해 장면별 대본과 화이트보드 일러스트를 생성하고, 드로잉 애니메이션·한국어 TTS·자막을 결합한 30~60초 숏폼 영상을 자동 제작하는 MVP 개발

### **핵심 기술**

**Python + OpenAI API + whiteboard-animator + FFmpeg + Remotion**

### **입력**

블로그 URL 또는 원문 텍스트

### **출력**

1080×1920 해상도의 30~60초 화이트보드 설명형 MP4 영상

### **핵심 기능**

1. 블로그 본문 자동 추출
2. AI 기반 핵심 내용 분석 및 대본 생성
3. 장면별 화이트보드 일러스트 자동 생성
4. 한국어 내레이션 및 자막 생성
5. 일러스트 드로잉 애니메이션 생성
6. 영상 자동 합성 및 MP4 출력

### **MVP 완료 기준**

**블로그 콘텐츠 1건을 입력하면 별도의 복잡한 수작업 없이 화이트보드 일러스트 숏폼 영상 초안이 자동 생성되어야 한다.**

추가로 서로 다른 주제의 블로그 3건 이상을 테스트해 자동화 성공 여부, 영상 품질, 생성 시간, API 비용을 기록한다.
