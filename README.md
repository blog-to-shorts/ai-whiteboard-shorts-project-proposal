# **AI 화이트보드 숏폼 자동 생성 파이프라인 MVP 구성안**

**기획 회의용 | 기업 요구사항 기반 기술 구성안**

## **1. 프로젝트 목표**

블로그 URL 또는 원문을 입력하면 AI가 핵심 내용을 분석하고, 장면별 대본과 화이트보드 일러스트를 생성한 뒤, **드로잉 애니메이션·한국어 내레이션·자막이 포함된 30~60초 세로형 MP4 영상 초안을 자동으로 제작**하는 MVP를 구현한다.

기업이 강조한 핵심은 화려한 웹 UI가 아니라 **입력부터 영상 생성까지 사람의 개입을 최소화한 AI 파이프라인의 완성도**다.

### **핵심 구현 원칙**

- **자동화:** 콘텐츠 입력 이후 대본·장면·이미지·음성·자막·영상 생성까지 자동 연결
- **화이트보드 스타일:** 단순 이미지 슬라이드가 아닌, 일러스트가 순차적으로 그려지는 영상 구현
- **설명 적합성:** 장면별 일러스트가 내레이션의 핵심 내용을 시각적으로 표현
- **일관성:** 전체 영상에서 흑백 라인아트 기반의 화이트보드 스타일 유지
- **수정 용이성:** 생성된 대본이나 장면을 최소한의 작업으로 수정·재생성할 수 있도록 구성

## **5. 핵심 데이터 구조: scenes.json**

전체 자동화를 위해 각 장면의 정보를 JSON 형태로 관리한다.

최종적으로 사용할 수 있는 구조의 예시

```json
{
  "title": "미스터리 기차역 이야기",
  "aspect_ratio": "9:16",
  "fps": 30,
  "target_duration": 45,
  "style_prompt": "Black and white whiteboard line art",
  "scenes": [
    {
      "id": 1,
      "narration": "폭설로 고립된 외딴 기차역.",
      "image_prompt": "A remote train station covered in snow",
      "image": "assets/images/scene_01.png",
      "audio": "assets/audio/scene_01.wav",
      "video": "videos/scene_01.mp4",
      "subtitle": "assets/subtitles/scene_01.srt",
      "duration": null
    }
  ]
}
```

실제 구현에서는 다음과 같이 처리한다.

1. OpenAI API가 장면별 대본과 이미지 프롬프트 생성
2. 이미지 생성 API가 장면별 PNG 파일 저장
3. TTS 엔진이 음성 파일 생성
4. Python이 실제 음성 길이를 측정하고 `duration` 기록
5. `whiteboard-animator`가 장면별 영상 생성
6. Remotion이 JSON 데이터를 기반으로 장면을 자동 배치

**장면 수를 코드에 고정하지 않고 JSON 데이터에 따라 자동 변경하는 것이 핵심**

## **6. 기업이 강조한 품질 검증 방안**

이번 프로젝트는 단순히 영상이 생성되는 것뿐 아니라 결과물의 활용 가능성도 확인해야 함

따라서 다음 항목을 검증하도록 설계한다.

| **검증 항목** | **검증 방법** |
| --- | --- |
| 자동화 성공 여부 | URL 입력부터 MP4 출력까지 수동 개입 없이 실행 |
| 대본 품질 | 원문의 핵심 정보 누락·왜곡 여부 확인 |
| 장면 적합성 | 내레이션과 이미지의 의미적 연결 확인 |
| 화풍 일관성 | 장면 간 선 굵기·색상·구도 비교 |
| 드로잉 품질 | 그림이 자연스럽게 나타나는지 확인 |
| 음성·자막 동기화 | 실제 발화와 자막 표시 시간 비교 |
| 영상 길이 | 최종 영상이 30~60초 범위인지 확인 |
| 생성 시간 | 입력부터 최종 MP4까지 소요 시간 측정 |
| 생성 비용 | 콘텐츠 1건당 API 사용 비용 계산 |
| 수정 용이성 | 대본 또는 이미지 수정 후 재렌더 가능 여부 확인 |

### **특히 중요한 검증 항목**

**장면 적합성과 드로잉 품질은 별도로 평가해야 함**

예를 들어 AI가 대본에 적합한 그림을 생성하더라도, `whiteboard-animator`가 그림을 무작위 순서로 그리면 설명 흐름이 자연스럽지 않을 수 있음

따라서 두 가지를 구분해서 확인해야 함

- **AI 이미지 품질:** 대본을 정확하게 시각화했는가?
- **드로잉 품질:** 그림이 자연스럽고 이해하기 쉬운 순서로 등장하는가?

이 부분은 기업이 강조한 ‘설명 과정을 직관적으로 표현’한다는 목표와 직접 연결됨

# **9. 최종 제안 구성**

### **프로젝트명**

**AI 기반 화이트보드 숏폼 자동 생성 파이프라인**

### **프로젝트 목적**

블로그 콘텐츠를 AI로 분석해 장면별 대본과 화이트보드 일러스트를 생성하고, 드로잉 애니메이션·한국어 TTS·자막을 결합한 30~60초 숏폼 영상을 자동 제작하는 MVP 개발

### **핵심 기술**

**Python + OpenAI API + whiteboard-animator + FFmpeg + Remotion**

whiteboard-animator github : https://github.com/masihsultani/whiteboard-animator  
FFmpeg github : https://github.com/FFmpeg/FFmpeg  
Remotion github : https://github.com/remotion-dev/remotion

### **입력**

블로그 URL 또는 원문 텍스트

### **출력**

1080×1920 해상도의 30~60초 화이트보드 설명형 MP4 영상

### **핵심 기능**

1. 블로그 본문 자동 추출
2. AI 기반 핵심 내용 분석 및 대본 생성
3. 장면별 화이트보드 일러스트 자동 생성
4. 한국어 내레이션 및 자막 생성
5. 일러스트 드로잉 애니메이션 생성
6. 영상 자동 합성 및 MP4 출력

### **MVP 완료 기준**

**블로그 콘텐츠 1건을 입력하면 별도의 복잡한 수작업 없이 화이트보드 일러스트 숏폼 영상 초안이 자동 생성되어야 한다.**

추가로 서로 다른 주제의 블로그 3건 이상을 테스트해 자동화 성공 여부, 영상 품질, 생성 시간, API 비용을 기록한다.

## 프로젝트 구조
